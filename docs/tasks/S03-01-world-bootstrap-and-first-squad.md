# S03-01 — Produce a seeded world, club, and first squad

**Status:** Done ✅ (S03-01, OPD-18)  
**Sprint:** 03 — Seeded playable world bootstrap  
**Source:** Technical plan §§6–7, 16, 18; PRD §§5, 74  
**Depends on:** S01-04, S02-02, S02-03

## What to do

Implement the Phase-0 bootstrap path that creates a world and generates a club with a squad of procedurally named, nationalized players. Limit initial competition/assignment semantics to the approved open-decision outcome.

## Acceptance criteria

- A bootstrap operation creates a world, club, manager assignment, and player squad under one `world_id`.
- Every generated player uses the shared player-generation subsystem and is persisted in the player schema.
- Bootstrap emits auditable world events for material generated state.
- A generated club and squad are retrievable through an authorized server API.
- The resulting world can receive its daily tick.

## Delivery evidence

- **AC1 — atomic bootstrap:** `internal/bootstrap.BootstrapWorld` runs in a single transaction: locks the world row (`FOR UPDATE`), guards provisioning status (404 unknown / 409 not-provisioning / 409 already-bootstrapped / 503 empty `ref` pools), inserts one `is_ai_controlled` club → one policy-bot `manager.managers` row (`is_policy_bot=TRUE`, `status='active'`, `current_club_id` wired) → 24 `person.people` + `player.players` rows (squad numbers 1–24). Admin endpoint `POST /api/admin/worlds/:id/bootstrap` returns 201 + `{club_id, club_name, manager_id, squad_size, random_seed, players}`.
- **AC2 — shared subsystem + player schema, persisted:** the squad is generated by `pkg/playergen` (weighted `ref.nationalities` + `ref.name_pool` loaded at runtime per OPD-13, `NameRegistry` collision avoidance, ages 17–33 with `date_of_birth = daysTruncate(COALESCE(launched_at, created_at)) − age`); rows land in `player.players` joined to `person.people`. `TestBootstrapWorldCreatesMaterial` asserts 24/24 rows, valid positions (≥2 GK), and DOB consistency.
- **AC3 — auditable events:** `CLUB_CREATED {club_id, club_name, manager_id, squad_size}` and `WORLD_BOOTSTRAPPED {club_count, squad_size, random_seed}` are inserted **in the bootstrap transaction** (actor `system`, world_tick 0); the int64 per-world seed is persisted on `WORLD_BOOTSTRAPPED.random_seed`. `TestBootstrapWorldCreatesMaterial` (2 events, seed round-trip) + `TestBootstrapWorldDeterministic` (identical seeds → identical squads via `newServiceWith`).
- **AC4 — authorized read API:** `GET /api/clubs` (caller's world derived from the manager row, OPD-15(3)) + `GET /api/clubs/:id` (club + policy-bot manager + 24-player squad with age; `404` across worlds). `TestHTTPBootstrapAndClubReads` covers 201/403/409/404 plus club identity/manager/squad shape; `TestBootstrapWorldGuards` covers the service-level guards.
- **AC5 — daily tick:** `TestBootstrappedWorldReceivesDailyTick` launches the bootstrapped world then fires `internal/scheduler.Service.FireTick("daily")` → `current_tick=1` and exactly one `WORLD_TICK` event for the world.
